**各服務的取得金鑰連結**

```typescript
const API_DOCS_LINKS = {
  googleTTS: "https://cloud.google.com/text-to-speech/docs/before-you-begin",
  gemini: "https://ai.google.dev/gemini-api/docs/api-key",
  replicate: "https://replicate.com/account/api-tokens",
  dId: "https://docs.d-id.com/reference/authentication",
  youtube: "https://developers.google.com/youtube/v3/getting-started"
};
```

**驗證邏輯**

各 API 金鑰的驗證方式:

1. **Google Cloud TTS**
   - 呼叫: `texttospeech.voices.list`
   - 成功條件: HTTP 200 且回傳語音列表
   - 失敗情況:
     - 401: "金鑰無效或已過期"
     - 403: "API 未啟用,請先在 Google Cloud Console 啟用 TTS API"
     - 網路錯誤: "無法連線到 Google Cloud,請檢查網路"

2. **Gemini API**
   - 呼叫: `models.list` 或簡單的 `generateContent` 測試
   - 成功條件: HTTP 200 且回傳模型列表
   - 失敗情況:
     - 401/403: "金鑰無效"
     - 429: "已達到免費額度限制"
     - 網路錯誤: "無法連線到 Gemini API"

3. **Replicate**
   - 呼叫: `GET https://api.replicate.com/v1/models`
   - 成功條件: HTTP 200
   - 失敗情況:
     - 401: "Token 無效"
     - 網路錯誤: "無法連線到 Replicate"

4. **D-ID**
   - 呼叫: `GET https://api.d-id.com/credits`
   - 成功條件: HTTP 200 且回傳額度資訊
   - 失敗情況:
     - 401: "金鑰無效"
     - 網路錯誤: "無法連線到 D-ID"

5. **YouTube Data API**
   - 驗證流程特殊,需要 OAuth 2.0:
   - 點擊「測試連線」時:
     1. 檢查 Client ID 和 Client Secret 是否已填寫
     2. 啟動 OAuth 2.0 授權流程 (詳見 05-youtube-upload-page.md)
     3. 成功取得 Access Token 後顯示 "金鑰有效"
   - 失敗情況:
     - Client ID/Secret 錯誤: "OAuth 設定無效"
     - 使用者取消授權: "授權已取消"

### 載入既有專案流程

1. **點擊專案卡片或「載入專案」按鈕**
2. **開啟檔案選擇器**:
   - 預設位置: 使用者文件/YTMaker3

3. **載入專案**:
   - 讀取 JSON 檔案
   - 驗證檔案格式 (詳見下方)
   - 若有效: 跳轉到專案上次離開的階段
   - 若無效: 顯示錯誤處理對話框 (詳見下方)

**專案檔案驗證邏輯**

載入專案時,依序檢查以下必要欄位:

```typescript
interface ProjectFile {
  version: string;           // 專案檔案格式版本 (必需)
  projectName: string;       // 專案名稱 (必需)
  createdAt: string;         // 建立時間 ISO 8601 (必需)
  lastModified: string;      // 最後修改時間 ISO 8601 (必需)
  currentStage: string;      // 當前階段 (必需)
  script?: {                 // 文稿資料 (選用,但若存在必須完整)
    originalText: string;
    segments: Array<{
      text: string;
      startTime: number;
      endTime: number;
      imagePrompt: string;
    }>;
  };
  voice?: string;            // 選用
  audioFile?: string;        // 選用
  images?: string[];         // 選用
  // ... 其他欄位
}
```

**檔案損壞的判斷條件**

判定為「檔案已損壞」,當發生以下任一情況:

1. **JSON 格式錯誤**:
   - 無法 parse JSON
   - 錯誤訊息: "JSON 格式錯誤"

2. **缺少必要欄位**:
   - 缺少 `version`, `projectName`, `createdAt`, `lastModified`, `currentStage`
   - 錯誤訊息: "缺少必要欄位: {欄位名稱}"

3. **欄位型別錯誤**:
   - 例如 `projectName` 不是字串,`createdAt` 不是有效 ISO 8601 日期
   - 錯誤訊息: "欄位型別錯誤: {欄位名稱}"

4. **階段資料不一致**:
   - `currentStage` 為 "script-editor",但 `script` 欄位為 null
   - `currentStage` 為 "video-preview",但 `audioFile` 或 `images` 為空
   - 錯誤訊息: "階段資料不一致"

5. **參照檔案不存在**:
   - `audioFile` 指向不存在的檔案路徑
   - `images` 陣列中的圖片檔案不存在
   - 錯誤訊息: "參照檔案不存在: {檔案路徑}"

**版本不相容處理**

若專案檔案的 `version` 與當前應用程式版本不相容:

```typescript
const CURRENT_PROJECT_VERSION = "1.0";
const COMPATIBLE_VERSIONS = ["1.0"]; // 支援的版本列表

// 未來版本可擴充:
// const COMPATIBLE_VERSIONS = ["1.0", "1.1", "1.2"];
```

- 若 `file.version` 不在 `COMPATIBLE_VERSIONS` 中:
  - 顯示警告對話框 (見下方)
  - 提供選項: [取消載入] [嘗試載入]

**部分恢復策略**

若專案檔案部分損壞,但核心資料完整,嘗試部分恢復:

1. **可恢復的情況**:
   - 缺少 `voice` 欄位 → 使用預設語音
   - 缺少 `lastModified` → 使用 `createdAt` 或當前時間
   - `images` 陣列部分圖片遺失 → 標記為「需重新生成」
   - `audioFile` 不存在 → 允許重新生成音訊

2. **恢復流程**:
   - 載入時顯示 Toast: "專案部分資料遺失,已嘗試自動修復"
   - 在對應頁面顯示警告 Banner: "部分資料已遺失,建議重新生成"
   - 提供「重新生成」按鈕

3. **不可恢復的情況**:
   - 缺少 `projectName`, `currentStage` 等核心欄位
   - `script.segments` 資料損壞 (文稿是核心資料)
   - 這些情況直接顯示錯誤對話框,不嘗試恢復
